### 🏛 Блок 1: Архитектура и High Availability (Отказоустойчивость)

Это база. Вас будут проверять на понимание того, как Exchange хранит данные и не падает.

**1. Серверные роли (Exchange 2013/2016/2019)**
*   **Вопрос:** Какие роли существуют в современных версиях Exchange?
*   **Ответ:** Начиная с 2013 года, ролей всего две: **Mailbox** (Почтовый ящик) и **Edge Transport** (Граничный транспорт). Роль Client Access (CAS) и Hub Transport были "упакованы" внутрь службы Mailbox. Edge Transport ставится отдельно, обычно в DMZ.
*   *Нюанс по Exchange 2019:* В нем больше нет роли Unified Messaging (UM). Голосовая почта теперь только через облако (Skype for Business Server / Teams).

**2. DAG (Database Availability Group)**
*   **Вопрос:** Что такое DAG и как он работает?
*   **Ответ:** DAG — это группа серверов Mailbox (до 16 штук), которая использует технологию **Windows Server Failover Clustering (WSFC)** и непрерывную репликацию логов транзакций для обеспечения высокой доступности.
*   **Вопрос:** Зачем нужен File Share Witness (FSW)?
*   **Ответ:** Для предотвращения **Split-Brain** (расщепления мозга). Если связь между площадками теряется, FSW (файловая шара на стороннем сервере) помогает кворуму (большинству узлов) решить, кто из сайтов "выжил" и должен примонтировать базы данных.
*   **Вопрос:** Что такое Activation Preference?
*   **Ответ:** Это приоритет монтирования копии базы данных. Если основная БД падает, Exchange смотрит, у какой пассивной копии приоритет (число) ниже, и монтирует её.

### 🛣 Блок 2: Mail Flow (Маршрутизация почты)

Почта должна ходить, и вы должны понимать, как она движется внутри сервера и за его пределами.

**1. Transport Pipeline**
*   **Вопрос:** Опишите путь письма внутри сервера Exchange (Transport Pipeline).
*   **Ответ:**
    1.  **Front End Transport** (на слушателях портов 25/587/465) — принимает письмо, делает базовые проверки.
    2.  **Hub Transport** (маршрутизация) — применяет правила транспорта, агентов антивируса/антиспама.
    3.  **Mailbox Transport** (доставка) — спускает письмо на уровень базы данных и кладет в конкретный ящик (через службу Mailbox Transport Delivery).

**2. Коннекторы (Connectors)**
*   **Receive Connectors:** Настраиваются на серверах Exchange. Определяют, *кто* и *как* может отправлять почту НА ваш сервер (например, анонимная отправка с принтеров или приложений через Relay).
*   **Send Connectors:** Определяют, *куда* Exchange должен отправлять почту наружу (например, через Smart Host провайдера или напрямую в интернет через MX-записи).

### ☁️ Блок 3: Гибридная среда (Hybrid) и Exchange Online

Сейчас "чистый" On-Premises Exchange встречается всё реже. Вас обязательно спросят про связь с Microsoft 365 (Office 365).

*   **Что такое HCW (Hybrid Configuration Wizard)?** Это мастер, который настраивает доверие (Organization Trust), синхронизирует конфигурации и создает нужные Send/Receive коннекторы между локальным Exchange и Exchange Online Protection (EOP).
*   **Mail Flow в гибриде:** Вы должны знать, что почта может ходить "напрямую" (Direct Mail Flow) между локальным сервером и M365 через TLS-коннекторы, либо через "Централизованный транспорт" (Centralized Mail Transport), когда вся облачная почта спускается в локальный Exchange для прохождения через локальные DLP-шлюзы или архиваторы.
*   **Связь с ADFS:** *Здесь пригодятся ваши знания!* Если вы используете федерацию (ADFS), то аутентификация пользователей в OWA (Outlook Web App) и ActiveSync идет через ваш локальный ADFS. Если используется Password Hash Sync (PHS) или Pass-through Auth (PTA), то Exchange Online аутентифицирует пользователей сам через Entra ID (Azure AD).
*   **Modern Authentication (OAuth):** Базовая аутентификация (Basic Auth) в Exchange Online полностью отключена. Вы должны понимать, как настраивать OAuth для интеграции локального Exchange с облаком (EvoSTS).

### 🔐 Блок 4: Безопасность (Самый горячий топик)

После атак **HAFNIUM (2021 год)**, когда хакеры массово взламывали локальные серверы Exchange через уязвимости нулевого дня (Zero-Day), вопросы безопасности стали обязательными.

*   **Как защитить локальный Exchange сегодня?**
    *   **Регулярные обновления (CU и SU):** Microsoft теперь выпускает Security Updates (SU) даже для старых CU.
    *   **Ограничение доступа к 443 порту:** OWA и ECP (панель управления) не должны "светиться" в интернет напрямую. Нужно прятать их за Reverse Proxy (например, F5, Kemp, Nginx, WAP) или использовать Conditional Access.
    *   **Отключение устаревших протоколов:** Отключить TLS 1.0/1.1, оставить только TLS 1.2/1.3.
*   **Что такое RBAC?** (Role-Based Access Control). В Exchange администраторы не имеют прав по умолчанию. Вы выдаете им роли (например, "Help Desk" для сброса паролей или "Recipient Management" для создания ящиков).

### 🛠 Блок 5: PowerShell и Траблшутинг

Интервьюер даст вам сценарий и спросит: "Что будешь делать / какие команды введешь?". Exchange Management Shell (EMS) — ваш главный инструмент.

**Топ команд, которые нужно знать наизусть:**
*   `Get-MailboxDatabaseCopyStatus` — посмотреть здоровье DAG (индексы, длина очереди копирования логов - CopyQueueLength / ReplayQueueLength).
*   `Test-ServiceHealth` — проверка работоспособности служб на сервере.
*   `Get-MessageTrackingLog` (или `Search-MessageTrackingReport`) — **самая частая задача**. "Пользователь говорит, что не получил письмо от клиента. Найди, где оно потерялось".
*   `Get-Queue` — посмотреть очереди на серверах. Если очередь растет, значит, есть проблема с маршрутизацией или коннектором.
*   `Test-Connection` / `Test-Mailflow` — проверка сетевой связности и отправки тестового письма.
*   `Test-OutlookConnectivity` / `Test-MapiConnectivity` — проверка доступности баз и профилей.

**Типичные сценарии на собеседовании:**
1.  **Сценарий:** *База данных в статусе "Dismounted" или "Failed and Suspended". Ваши действия?*
    *   *Ответ:* Смотрю `Get-MailboxDatabaseCopyStatus`. Если проблема в логах (Log truncation failed), проверяю место на диске, бэкапы (VSS). Если база "повреждена" (Dirty Shutdown), возможно, придется использовать `eseutil /r` (мягкое восстановление) или `eseutil /p` (жесткое, с потерей данных - только в крайнем случае!), либо просто переключиться на здоровую копию в DAG и пересоздать (Reseed) поврежденную.
2.  **Сценарий:** *Outlook постоянно запрашивает пароль.*
    *   *Ответ:* Проверяю, не отключена ли Modern Authentication. Проверяю Autodiscover (через `Test-OutlookAutoDiscover`). Смотрю, нет ли проблем с сертификатами (Split-Brain DNS, когда внутри сети сертификат не совпадает с именем). Проверяю, не заблокирован ли аккаунт в AD.
3.  **Сценарий:** *Письма уходят, но не доходят до конкретного домена.*
    *   *Ответ:* Смотрю `Get-Queue`. Если там виснут письма с ошибкой `400 4.4.7 Message delayed` или `500 5.0.0`, смотрю Message Tracking. Проверяю DNS (MX записи того домена), проверяю Send Connector, проверяю, не попали ли мы в их черные списки (Blacklists).

### 🧭 Блок 6: Клиентский доступ (Client Access)

*   **Autodiscover:** Как Outlook находит настройки?
    1.  Сначала ищет SCP (Service Connection Point) в локальном Active Directory.
    2.  Если не нашел (или клиент вне домена), идет по DNS: `autodiscover.domain.com`.
    3.  Затем делает HTTP-redirect и запрашивает `autodiscover.xml`.
*   **Пространства имен (Namespaces):** В современных версиях Exchange рекомендуется использовать **минимум** пространств имен (например, `mail.domain.com` для всего: OWA, EWS, MAPI, Autodiscover) и настраивать их через DNS и балансировщики, чтобы избежать проблем с сертификатами.
*   **MAPI over HTTP:** Пришел на смену Outlook Anywhere (RPC over HTTP). Работает быстрее, лучше переносит обрывы связи, позволяет приостанавливать и возобновлять сессии.

### 💡 Секретные фишки, которые выделят вас на собеседовании

1.  **Упомяните Exchange Server Role Requirements Calculator.**
    *   *Как сказать:* "При планировании железа или миграции я всегда использую официальный Excel-калькулятор от Microsoft (Exchange Calculator). Он учитывает IOPS, количество сообщений в день, DAG и оверхед на бэкапы, чтобы правильно подобрать диски и RAM". (Интервьюеры обожают, когда кандидаты знают этот инструмент).
2.  **Знание про Exchange SE (Subscription Edition).**
    *   *Как сказать:* "Я в курсе, что эпоха классических 'коробочных' версий заканчивается. Microsoft анонсировала Exchange Server Subscription Edition (SE), которая будет требовать обязательной подписки и, вероятно, изменит модель обновлений". Это покажет, что вы следите за рынком.
3.  **Индексы (Search).**
    *   В Exchange 2016/2019 поиск (Exchange Search / Big Funnel) был перенесен прямо в файл базы данных (.edb). Если вы знаете, что такое *Content Index* и как его перестраивать (`ResetSearchIndex`), это большой плюс.
4.  **Бэкапы и усечение логов (Log Truncation).**
    *   Обязательно скажите: "Бэкап Exchange — это не просто копирование файлов. VSS-бэкакпер (например, Veeam или Windows Server Backup) должен корректно отрабатывать с Exchange Writer, чтобы после успешного бэкапа **транзакционные логи усеклись (truncated)**. Иначе диски забьются за день".
