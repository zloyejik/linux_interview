# 🔹 Краткий курс BASH для собеседования

Этот материал сфокусирован на темах, которые **регулярно проверяют на интервью** (DevOps/SRE/Backend/SysAdmin). Структура: база → паттерны → инструменты → лайфхаки для ответов.

---

## 1. Основы и запуск
```bash
#!/usr/bin/env bash  # предпочтительно (ищет bash в PATH)
# или #!/bin/bash     # жёсткий путь
chmod +x script.sh   # делаем исполняемым
./script.sh          # запуск
```
- `#` – комментарий до конца строки
- `bash -n script.sh` – проверка синтаксиса без запуска
- `bash -x script.sh` – трассировка выполнения

---

## 2. Переменные и спецпараметры
```bash
VAR="value"          # без пробелов вокруг =
echo "$VAR"          # ВСЕГДА в кавычках при использовании
```
| Переменная | Значение |
|------------|----------|
| `$0`       | Имя скрипта |
| `$1`..`$9` | Позиционные аргументы |
| `$#`       | Количество аргументов |
| `$@`       | Все аргументы (как отдельные слова) |
| `$*`       | Все аргументы (одной строкой) |
| `$?`       | Код выхода последней команды |
| `$$`       | PID текущего процесса |
| `$!`       | PID последнего фонового процесса |
| `$_`       | Последний аргумент предыдущей команды |

- `export VAR=val` – делает переменную доступной в дочерних процессах
- `local VAR=val` – внутри функций (область видимости ограничена функцией)

## 3. Кавычки и подстановки
| Тип | Поведение |
|-----|-----------|
| `"..."` | Подставляет `$VAR`, `$(cmd)`, `\n` и т.д. |
| `'...'` | Строгая строка, ничего не раскрывается |
| `$(cmd)` | Подстановка вывода команды (предпочтительно) |
| `` `cmd` `` | Старый синтаксис, не вкладывается, не рекомендуется |
| `\` | Экранирование символа |

---

## 4. Потоки, перенаправление, пайпы
```bash
cmd > file      # stdout в файл (перезапись)
cmd >> file     # добавление в конец
cmd 2> err.log  # stderr в файл
cmd &> out.log  # stdout и stderr в один файл
cmd 2>&1        # stderr → stdout
```
- Дескрипторы: `0` (stdin), `1` (stdout), `2` (stderr)
- `|` – передача stdout левой команды в stdin правой
- `tee file` – выводит на экран И пишет в файл
- `</dev/null`, `>/dev/null 2>&1` – подавление вывода (часто в cron)

## 5. Условия и тесты
```bash
if [[ условие ]]; then
    ...
elif [[ ... ]]; then
    ...
else
    ...
fi
```
**`[[ ]]` vs `[ ]`**: `[[ ]]` – встроенная в bash, поддерживает `&&`, `||`, `=~`, не требует экранирования пробелов.

| Тест | Значение |
|------|----------|
| `-e file` | Существует |
| `-f file` | Обычный файл |
| `-d dir`  | Директория |
| `-r/-w/-x` | Чтение/Запись/Выполнение |
| `-z "$str"` | Строка пустая |
| `-n "$str"` | Строка не пустая |
| `"$a" = "$b"` | Строки равны |
| `$a -eq $b` | Числа равны (`-ne`, `-gt`, `-lt`, `-ge`, `-le`) |

Пример: `if [[ -f "$cfg" && -r "$cfg" ]]; then`

## 6. Циклы и чтение данных
```bash
# for
for i in {1..5}; do echo "$i"; done
for f in *.log; do gzip "$f"; done

# while
while [[ $count -lt 10 ]]; do
    ((count++))
done

# Чтение файла ПОСТРОЧНО (без потери пробелов!)
while IFS= read -r line; do
    echo "LINE: $line"
done < input.txt
```
- `break`, `continue` – работают как в других языках
- `IFS=` + `-r` в `read` предотвращает обрезку пробелов и раскрытие `\`

## 7. Функции
```bash
log_msg() {
    local level="$1"
    local msg="$2"
    echo "[$(date +'%T')] [$level] $msg" >&2
}

log_msg "ERROR" "Disk full"
```
- Аргументы функции: `$1`, `$2`, `$@` (локальные для функции)
- `return 0..255` – код выхода (только числа!)
- Возврат текста: через `echo` и захват вывода `result=$(my_func)`

## 8. Текстовая обработка (топ на интервью)
| Утилита | Типичное использование |
|---------|------------------------|
| `grep`  | `grep -i -E "err|warn" log \| grep -v debug` |
| `sed`   | `sed -i 's/old/new/g' file`, `sed -n '1,5p'`, `sed '/pattern/d'` |
| `awk`   | `awk -F: '$3 > 1000 {print $1}' /etc/passwd` |
| `cut`   | `cut -d: -f1,3 file` |
| `sort`/`uniq` | `sort file \| uniq -c \| sort -nr` |
| `wc`    | `wc -l` (строки), `-w` (слова), `-c` (байты) |
| `xargs` | `find . -name "*.tmp" -print0 \| xargs -0 rm` (безопасно с пробелами) |
| `tr`    | `tr '[:lower:]' '[:upper:]'`, `tr -d '\r'` |

💡 `awk` часто спрашивают: `$0` – вся строка, `$1..$N` – поля, `NR` – номер строки, `NF` – кол-во полей, `BEGIN/END` блоки.

## 9. Лучшие практики (обязательно упомянуть)
```bash
#!/usr/bin/env bash
set -euo pipefail
```
- `-e` → выход при ошибке любой команды
- `-u` → ошибка при использовании необъявленной переменной
- `-o pipefail` → код выхода пайпа = код первой упавшей команды
- Всегда кавычки: `"$VAR"`, `"${VAR[@]}"`
- Проверка аргументов: `[[ $# -ne 2 ]] && { echo "Usage: $0 a b"; exit 1; }`
- Временные файлы: `tmp=$(mktemp)` + `trap 'rm -f "$tmp"' EXIT`
- Избегайте: `eval`, парсинг `ls`, `for f in $(find ...)` (ломаются на пробелах)

## ❓ Типичные вопросы на собеседовании (с краткими ответами)

| Вопрос | Ключевой ответ |
|--------|----------------|
| Разница `[ ]` и `[[ ]]`? | `[ ]` – POSIX, требует экранирования `&&`/`||`, не поддерживает `=~`. `[[ ]]` – bash-встроенный, безопаснее, поддерживает логические операторы и регулярки. |
| Почему `` `cmd` `` хуже `$(cmd)`? | `` ` `` не вкладывается, сложнее читать, проблемы с экранированием. `$(cmd)` читаемее и вложен. |
| Как обработать файлы с пробелами в именах? | `find ... -print0 \| xargs -0 ...` или цикл `while IFS= read -r -d '' file; do ... done < <(find ... -print0)` |
| Что делает `set -euo pipefail`? | Строгий режим: ошибка команды → выход, необъявленная переменная → ошибка, пайп → учитывает код всех команд, не только последней. |
| Как передать переменную через SSH? | `ssh user@host "MY_VAR='$val' bash -s" <<'EOF'` или `export VAR; ssh user@host 'echo $VAR'` (зависит от кавычек) |
| Как ждать завершения всех фоновых задач? | `wait` (без аргументов ждёт все, с PID – конкретную) |
| Почему `echo $VAR` без кавычек опасно? | Word splitting и globbing: пробелы разбивают строку, `*` раскрывается в список файлов. |
