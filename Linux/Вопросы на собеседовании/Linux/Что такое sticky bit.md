**Sticky bit** (в русской литературе часто называется «липкий бит») — это специальный бит прав доступа в Unix-подобных операционных системах (Linux, macOS и др.), который меняет стандартное поведение файловой системы.

### 🎯 Современное основное применение
Сегодня sticky bit применяется почти исключительно к **каталогам (директориям)**. 

Если у директории установлен sticky bit, то **удалять или переименовывать файлы внутри неё может только**:
1. Владелец самого файла.
2. Владелец этой директории.
3. Суперпользователь (`root`).

Это правило работает **даже если** у других пользователей есть права на запись (`w`) в эту директорию. Без sticky bit любой пользователь с правами на запись в папку мог бы удалить или переименовать любой файл в ней, независимо от того, кто является владельцем файла.

**Классический пример**: системная директория `/tmp`. Она доступна для записи всем пользователям, чтобы программы могли создавать там временные файлы. Благодаря sticky bit (права обычно выглядят как `1777`) пользователь А не может случайно или намеренно удалить временный файл пользователя Б.

---

### ⚙️ Как установить и проверить

**1. Установка sticky bit:**
- С помощью буквенного обозначения:  
  `chmod +t /путь/к/директории`
- С помощью восьмеричного (цифрового) кода (добавляется `1` перед основными правами):  
  `chmod 1777 /путь/к/директории`  
  *(где `1` — это sticky bit, а `777` — полные права `rwx` для владельца, группы и остальных)*.

**2. Как увидеть sticky bit:**
Выполните команду `ls -l` для директории. Обратите внимание на последний символ в строке прав доступа:
- `drwxrwxrw`t` — буква **`t`** означает, что sticky bit установлен **и** у группы «остальные» (others) есть право на выполнение (`x`).
- `drwxrwxrw`T` — буква **`T`** (заглавная) означает, что sticky bit установлен, **но** права на выполнение (`x`) у «остальных» отсутствуют.

### 📜 Историческая справка
Изначально (в ранних версиях Unix) sticky bit применялся к **исполняемым файлам**. Он указывал операционной системе, что после завершения программы её код следует оставить в области подкачки (swap) или в оперативной памяти. Это позволяло быстрее запускать программу в следующий раз (например, так работали важные системные утилиты вроде текстового редактора `vi`). 

В современных системах с продвинутым управлением памятью эта функция для файлов устарела и не используется (в Linux она была полностью удалена из ядра, начиная с версии 2.4). Теперь этот бит зарезервирован исключительно для управления правами в директориях.
