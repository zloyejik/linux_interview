Мониторинг дисковой подсистемы и понимание разницы между интерфейсами — критически важные навыки для IT-инженера. Разделим ответ на две логические части.

---

### Часть 1. Какие параметры дисков (HDD/SSD) мониторить

Мониторинг делится на два уровня: **здоровье железа (S.M.A.R.T.)** и **производительность на уровне ОС**.

#### 1. S.M.A.R.T. (Health & Reliability)
Для сбора используйте `smartctl` (пакет `smartmontools`) или экспортеры (например, `node_exporter` с флагом `--collector.smartctl`).

**Для HDD (механических дисков):**
*   **Reallocated Sector Count (ID 05):** Количество переназначенных секторов. Рост = физическая деградация поверхности. *Критично.*
*   **Current Pending Sector Count (ID C5):** Нестабильные сектора, ожидающие переназначения. *Предвестник скорой смерти.*
*   **Uncorrectable Sector Count (ID C6):** Ошибки, которые не удалось исправить при чтении/записи. *Критично.*
*   **Spin Retry Count (ID 10):** Попытки раскрутки шпинделя. Рост указывает на проблемы с механикой или питанием.
*   **Power-On Hours (ID 09):** Наработка в часах. Полезно для планирования превентивной замены (обычно после 30-50 тыс. часов риск растет).
*   **Temperature (ID 194 / C2):** Перегрев (>50-55°C) резко снижает срок службы.

**Для SSD / NVMe:**
*   **Percentage Used / Media Wearout Indicator:** Процент исчерпания ресурса перезаписи. Если достигает 100%, диск переходит в режим read-only.
*   **Available Spare / Spare Blocks:** Процент оставшихся резервных блоков памяти. Падение ниже порога (обычно 10%) — критический алерт.
*   **Data Units Read/Written (TBW):** Общий объем записанных данных. Сравнивайте с заявленным производителем ресурсом (TBW).
*   **Critical Warning (для NVMe):** Битовая маска критических ошибок от контроллера (температура, надежность, read-only режим).

#### 2. Производительность (OS Level)
Инструменты: `iostat -xz 1`, `dstat`, Prometheus/Grafana.
*   **`%util` (Утилизация):** Процент времени, когда диск был занят обработкой запросов. Значение, стабильно близкое к 100%, означает, что диск — узкое место (bottleneck). *Для NVMe этот метрика менее показательна из-за огромной параллельности, там лучше смотреть на задержки.*
*   **`await` (Latency):** Среднее время обслуживания запроса (в мс). Для HDD норма < 10-15 мс, для SSD < 1-2 мс, для NVMe < 0.5 мс. Рост `await` при низкой загрузке — признак деградации диска или проблем с контроллером.
*   **IOPS (r/s, w/s):** Количество операций ввода-вывода в секунду.
*   **Throughput (rkB/s, wkB/s):** Пропускная способность в КБ/МБ в секунду.

### Часть 2. Отличия SATA от NVMe

Главное заблуждение: думать, что это просто "разные разъемы". На самом деле, это **принципиально разные архитектуры, протоколы и шины**.

| Характеристика | SATA (Serial ATA) | NVMe (Non-Volatile Memory express) |
| :--- | :--- | :--- |
| **Физическая шина** | SATA (специализированная шина для дисков) | PCIe (шина процессора, прямая связь с CPU) |
| **Протокол** | AHCI (Advanced Host Controller Interface) | NVMe (специально создан для флеш-памяти) |
| **Макс. скорость** | ~600 МБ/с (SATA III) | 3 000 – 14 000+ МБ/с (зависит от версии PCIe) |
| **IOPS (случайные)** | ~50 000 – 100 000 | 500 000 – 1 500 000+ |
| **Задержка (Latency)** | ~100 мкс | ~10–20 мкс |
| **Очереди команд** | **1 очередь**, глубина до 32 команд | **До 64 000 очередей**, глубина до 64 000 команд в каждой |
| **Нагрузка на CPU** | Высокая на один IOPS (из-за блокировок и прерываний) | Крайне низкая (эффективная работа с MSI-X прерываниями на каждое ядро) |
| **Форм-факторы** | 2.5", 3.5", M.2 (SATA) | M.2, U.2, U.3, E1.S, PCIe-плата (AIC) |

#### Глубокое погружение: Почему NVMe быстрее?

1. **Протокол AHCI vs NVMe:**
   * **AHCI** создавался в эпоху HDD. Он оптимизирован для механики: одна очередь команд, ожидание поворота диска, высокие накладные расходы на каждое прерывание CPU. Для SSD это "бутылочное горлышко".
   * **NVMe** создан с нуля для флеш-памяти. Он позволяет каждому ядру CPU иметь свою собственную очередь команд, обращаясь к контроллеру диска напрямую через PCIe, минуя лишние прослойки.

2. **Шина PCIe:**
   SATA III ограничен пропускной способностью ~6 Гбит/с (после кодирования 8b/10b это ровно 600 МБ/с). NVMe использует линии PCIe (x4). Одна линия PCIe 4.0 дает ~2 ГБ/с, значит x4 дает ~8 ГБ/с (8000 МБ/с).

3. **Важное предостережение про M.2:**
   **M.2 — это только форм-фактор (форма платы), а не протокол!**
   * Диск M.2 может быть **SATA** (имеет два "ключа" (выемки) на коннекторе, обычно B+M, скорость до 600 МБ/с).
   * Диск M.2 может быть **NVMe** (имеет один "ключ", обычно M, скорость от 3000 МБ/с).
   * Всегда проверяйте спецификацию материнской платы: некоторые слоты M.2 поддерживают только SATA, некоторые только NVMe, некоторые оба режима.

#### Когда что использовать?

*   **SATA (HDD):** Холодное хранение, бэкапы, видеонаблюдение, файловые помойки, где важна цена за гигабайт, а не скорость.
*   **SATA (SSD):** Бюджетные рабочие станции, апгрейд старых систем, вторичные диски для игр/софта, где скорость 500 МБ/с достаточна.
*   **NVMe:** Базы данных (PostgreSQL, ClickHouse и т.д.), виртуализация (Proxmox, VMware), высоконагруженные веб-серверы, компиляция кода, системные диски современных ОС.

### Резюме для мониторинга в IT-инфраструктуре
Настройте алерты в вашей системе мониторинга (Zabbix/Prometheus) на:
1. `smartctl` атрибуты `Reallocated_Sector_Ct` > 0 (для HDD) и `Available_Spare` < 10% (для SSD).
2. `iostat` метрику `await` > 20 мс для SSD и > 50 мс для HDD в течение продолжительного времени.
3. Температуру NVMe дисков > 70°C (многие современные NVMe начинают троттлить производительность при 75-80°C).
