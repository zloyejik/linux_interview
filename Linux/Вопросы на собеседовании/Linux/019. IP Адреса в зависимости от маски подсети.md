## 🧮 Формулы расчёта

```
Всего адресов = 2^(32 - CIDR)
Доступных хостов = 2^(32 - CIDR) - 2  (для масок /30 и крупнее)
```

**Пример для /24:**
- 32 − 24 = 8 бит под хосты
- 2⁸ = 256 всего адресов
- 256 − 2 = 254 доступных для устройств

---

## 🔑 Ключевые моменты

1. **Сетевой адрес** (первый в подсети) — идентифицирует саму сеть, не назначается хостам
2. **Широковещательный адрес** (последний в подсети) — для рассылки всем хостам сети
3. **Маска /32** — один конкретный хост (часто используется для маршрутов)
4. **Маска /31** — только для point-to-point соединений (оба адреса рабочие)
5. **Чем меньше число CIDR** → тем больше сеть → тем меньше подсетей можно создать

## 💡 Практический пример

```
Сеть: 192.168.1.0/26
- Маска: 255.255.255.192
- Всего адресов: 64
- Доступно хостам: 62
- Диапазон: 192.168.1.1 – 192.168.1.62
- Сетевой адрес: 192.168.1.0
- Broadcast: 192.168.1.63
```

### 1. Поймите базовый паттерн (Степени двойки)
Вся основа сабнеттинга (subnetting) строится на степенях двойки. Вам нужно довести до автоматизма только одну таблицу. Запомните количество адресов в блоке для последних октетов:

| CIDR | Маска подсети | Всего адресов | Полезных хостов | Шаг (Magic Number) |
|------|---------------|---------------|-----------------|---------------------|
| /24  | 255.255.255.0 | 256           | 254             | 256                 |
| /25  | 255.255.255.128| 128          | 126             | 128                 |
| /26  | 255.255.255.192| 64           | 62              | 64                  |
| /27  | 255.255.255.224| 32           | 30              | 32                  |
| /28  | 255.255.255.240| 16           | 14              | 16                  |
| /29  | 255.255.255.248| 8            | 6               | 8                   |
| /30  | 255.255.255.252| 4            | 2               | 4                   |

**Лайфхак:** Заметьте, что "Шаг" (Magic Number) и "Всего адресов" — это одно и то же число. Если вы помните шаг, вы знаете всё.

---

### 2. Метод "Магического числа" (Magic Number Method)
Этот метод популяризирован в англоязычной литературе (например, в книгах Wendell Odom). Он позволяет мгновенно вычислять границы подсетей без перевода в двоичный код.
- **Формула:** `256 - значение интересующего октета маски подсети = Магическое число`.
- **Пример:** Маска `/26` → `255.255.255.192`. Интересующий октет: 4-й (значение 192).
- `256 - 192 = 64`. 
- Значит, подсети делятся с шагом 64: `0, 64, 128, 192`. 
- Если ваш IP `192.168.1.100/26`, он попадает в подсеть `192.168.1.64` (диапазон 64–127, где 64 – сетевой, 127 – broadcast).

---

### 3. Визуализация и двоичное представление
Не пытайтесь запомнить все маски. Запомните, как выглядят биты:
- `/24` = `11111111.11111111.11111111.00000000`
- `/25` = `11111111.11111111.11111111.10000000` (1 бит для сети)
- `/26` = `11111111.11111111.11111111.11000000` (2 бита для сети)

Каждый сдвиг маски на 1 вправо (увеличение CIDR на 1) **делит количество хостов пополам**, а количество подсетей удваивает. Это зеркальная зависимость, которую легко представить визуально.

### 6. Мнемотехника для часто используемых масок
- **/30**: "Точка-точка" (Point-to-Point). Всего 4 адреса, 2 полезных. Идеально для линков между роутерами.
- **/29**: "Маленький офис". 8 адресов, 6 полезных.
- **/24**: "Классический LAN". 256 адресов, 254 полезных.
- Связь: `/30` → `/29` (+4 адреса) → `/28` (+8 адресов) → `/27` (+16 адресов). При движении влево (уменьшение CIDR) размер блока удваивается.
