**Runlevel (уровень запуска)** в Linux — это состояние системы, которое определяет, какие системные службы и процессы будут запущены после загрузки операционной системы. Эта концепция исторически связана с системой инициализации **SysVinit**, но в современных дистрибутивах она эволюционировала в систему **systemd** (где уровни запуска заменены на "targets" или цели), сохраняя обратную совместимость.

---

### Классические уровни запуска (SysVinit)
Традиционно в Linux существует 7 основных уровней запуска (от 0 до 6):

| Уровень | Название | Описание |
| :---: | :--- | :--- |
| **0** | Halt | Остановка системы (выключение). Никогда не устанавливается как уровень запуска по умолчанию. |
| **1** | Single-user mode | Однопользовательский режим (или режим восстановления/rescue). Используется для административных задач, ремонта файловой системы, сброса паролей. Сеть и графический интерфейс не запускаются. |
| **2** | Multi-user mode (без сети/NFS) | Многопользовательский режим. В **Debian/Ubuntu** это стандартный режим с сетью, но без графического интерфейса. В **RHEL/CentOS** historically это режим без поддержки NFS. |
| **3** | Multi-user mode (с сетью) | Полноценный многопользовательский текстовый режим (CLI) с поддержкой сети. Стандарт для серверов. |
| **4** | User-definable | Не используется по умолчанию. Зарезервирован для пользовательских сценариев. |
| **5** | Multi-user mode с GUI | Многопользовательский режим с сетью и графическим интерфейсом (X11/Wayland). Стандарт для рабочих станций. |
| **6** | Reboot | Перезагрузка системы. Никогда не устанавливается как уровень запуска по умолчанию. |

> *Примечание:* В некоторых дистрибутивах (например, Debian и его производных) уровни 2, 3, 4 и 5 по умолчанию настроены одинаково (многопользовательский режим с сетью), а различия задаются вручную администратором.

---

### Управление runlevel в SysVinit
- **Просмотр текущего уровня**:  
  `runlevel` или `who -r`
- **Изменение уровня запуска**:  
  `telinit <число>` или `init <число>` (например, `telinit 3` для перехода в текстовый режим).

---

### Современный подход: Systemd и "Targets"
В современных дистрибутивах (Ubuntu 16.04+, CentOS 7+, Debian 8+, Fedora и др.) используется **systemd**. Он заменил концепцию runlevel на более гибкую систему **targets** (целей), но для обратной совместимости создал символические ссылки, имитирующие старые уровни.

#### Соответствие runlevel и systemd targets:
| Runlevel | Systemd Target | Описание |
| :---: | :--- | :--- |
| 0 | `runlevel0.target` → `poweroff.target` | Выключение |
| 1 | `runlevel1.target` → `rescue.target` | Режим восстановления |
| 2, 3, 4 | `runlevel2.target`, `runlevel3.target`, `runlevel4.target` → `multi-user.target` | Многопользовательский режим (CLI) |
| 5 | `runlevel5.target` → `graphical.target` | Многопользовательский режим с GUI |
| 6 | `runlevel6.target` → `reboot.target` | Перезагрузка |

#### Управление в Systemd:
- **Просмотр текущего целевого состояния**:  
  `systemctl get-default`
- **Просмотр всех загруженных targets**:  
  `systemctl list-units --type=target`
- **Изменение целевого состояния по умолчанию** (например, сделать загрузку без GUI):  
  `sudo systemctl set-default multi-user.target`
- **Мгновенное переключение в другой режим** (без перезагрузки):  
  `sudo systemctl isolate multi-user.target` (аналог `telinit 3`)  
  `sudo systemctl isolate graphical.target` (аналог `telinit 5`)

---

### Краткий итог
- **Runlevel** — это устаревшая, но всё ещё понятная и используемая (через совместимость) концепция определения состояния загрузки Linux.
- Для **серверов** обычно используется уровень **3** (`multi-user.target`), так как графический интерфейс излишен и потребляет ресурсы.
- Для **рабочих станций** используется уровень **5** (`graphical.target`).
- В современной административной практике рекомендуется использовать команды `systemctl`, а не `init`/`telinit`.

Если вам нужно узнать текущий уровень запуска на вашей системе, вы можете выполнить команду `runlevel` или `systemctl get-default`, и я помогу расшифровать результат!
