# Модель OSI (Open Systems Interconnection)

**Модель OSI** — это эталонная модель взаимодействия открытых систем, разработанная Международной организацией по стандартизации (ISO) в 1984 году. Она описывает, как данные передаются по сети от одного устройства к другому, разделяя процесс на **7 уровней**.

---

## 📊 7 уровней модели OSI (снизу вверх)

| Уровень | Название (англ./рус.) | Единица данных | Примеры протоколов/технологий |
|---------|----------------------|----------------|------------------------------|
| **7** | Application / Прикладной | Данные | HTTP, HTTPS, FTP, SMTP, DNS, SSH |
| **6** | Presentation / Представления | Данные | SSL/TLS, JPEG, MPEG, ASCII, Unicode |
| **5** | Session / Сеансовый | Данные | NetBIOS, RPC, PPTP |
| **4** | Transport / Транспортный | Сегменты / Дейтаграммы | TCP, UDP, SCTP |
| **3** | Network / Сетевой | Пакеты | IP, ICMP, IPSec, routers |
| **2** | Data Link / Канальный | Кадры (фреймы) | Ethernet, Wi-Fi (802.11), MAC, switches |
| **1** | Physical / Физический | Биты | Кабели (UTP, оптоволокно), хабы, сигналы |

---

## 🔑 Ключевые принципы

### Инкапсуляция данных
При передаче данные проходят сверху вниз, и на каждом уровне добавляется свой заголовок:
```
[Данные] 
→ + заголовок L5-7 
→ + заголовок TCP/UDP (L4) 
→ + заголовок IP (L3) 
→ + заголовок Ethernet (L2) 
→ преобразование в биты (L1)
```

### Разделение ответственности
- Каждый уровень решает строго определённую задачу
- Уровни взаимодействуют только с соседними
- Возможность заменять реализации одного уровня без изменения других

---

## 🛠 Практическое применение

✅ **Диагностика сетей**: Помогает локализовать проблему (физический обрыв, ошибка маршрутизации, сбой приложения)  
✅ **Обучение**: База для понимания сетевых технологий  
✅ **Стандартизация**: Производители оборудования ориентируются на модель при разработке  
✅ **Сертификации**: Основа экзаменов CCNA, CompTIA Network+, и других

## ⚠️ Важное замечание

Модель OSI — **теоретическая**. В реальности используется более простая модель **TCP/IP** (4 уровня), но понимание OSI критически важно для:
- Глубокого анализа сетевых проблем
- Понимания работы протоколов
- Профессионального роста в IT-инфраструктуре

Протоколы **TCP/IP** — это не один протокол, а целый стек (набор) протоколов, поэтому они работают на **нескольких уровнях** сетевых моделей. 

Если рассматривать самую распространенную **модель OSI (7 уровней)**, то основные протоколы стека TCP/IP распределяются так:

1. **IP (Internet Protocol)** работает на **Сетевом уровне (Network Layer, Уровень 3)**. Он отвечает за адресацию (IP-адреса) и маршрутизацию пакетов данных между сетями.
2. **TCP (Transmission Control Protocol)** работает на **Транспортном уровне (Transport Layer, Уровень 4)**. Он отвечает за надежную доставку данных, установление соединения, контроль целостности и порядка получения пакетов.

Если рассматривать собственную **модель TCP/IP (4 уровня)**, то стек выглядит так:
- **Уровень сетевого доступа (Network Access Layer)**: аналог канального и физического уровней OSI (Ethernet, Wi-Fi и т.д.).
- **Межсетевой уровень (Internet Layer)**: здесь работает **IP**, а также ICMP, ARP.
- **Транспортный уровень (Transport Layer)**: здесь работают **TCP** и UDP.
- **Прикладной уровень (Application Layer)**: здесь работают протоколы, использующие TCP/IP (HTTP, FTP, SMTP, DNS и др.).

**Краткий итог:** 
- **IP** работает на **3-м уровне** (сетевом).
- **TCP** работает на **4-м уровне** (транспортном). 
Вместе они образуют основу передачи данных в интернете, связывая эти два уровня.


Протокол **UDP** (User Datagram Protocol) работает на **Транспортном уровне** (Transport Layer).

Если рассматривать основные сетевые модели:

1. **В модели OSI:** Это **4-й уровень** (Транспортный уровень / Transport Layer).
2. **В модели TCP/IP:** Это также **Транспортный уровень** (Transport Layer).

**Роль UDP на этом уровне:**
UDP работает на одном уровне с протоколом TCP, но имеет совершенно другую философию. Если TCP гарантирует доставку, контролирует порядок пакетов и устанавливает соединение, то UDP работает по принципу «отправил и забыл» (без установки соединения и без гарантий доставки). 

**Зачем это нужно:**
Отсутствие служебной информации и проверок делает UDP гораздо более быстрым и легким для процессора. Именно поэтому на транспортном уровне поверх UDP работают протоколы, где скорость и минимальная задержка важнее идеальной точности:
* **DNS и DHCP** (быстрые короткие запросы).
* **VoIP и видеоконференции** (задержка или потеря пары кадров критичнее, чем их идеальная доставка).
* **Онлайн-игры** (состояние мира обновляется постоянно, старые данные не нужны).
* **Стриминг видео и аудио**.
