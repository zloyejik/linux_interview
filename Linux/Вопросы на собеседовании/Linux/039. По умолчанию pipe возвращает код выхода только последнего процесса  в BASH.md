Отличный вопрос! Это одна из самых коварных тем в Bash. По умолчанию **pipe возвращает код выхода только последнего процесса**, что часто приводит к скрытым багам.

---

### Проблема по умолчанию

```bash
false | echo "Hello"
echo $?  # Выведет: 0 (код выхода echo, а не false!)
```

Даже если первая команда упала (`false`), pipe вернет `0`, потому что `echo` отработал успешно. Это классическая ловушка.

---

### Решение 1: `PIPESTATUS` (Массив кодов всех процессов)

Bash хранит коды возврата **всех** процессов в pipe в специальном массиве `PIPESTATUS`.

```bash
false | grep "test" | wc -l
echo "${PIPESTATUS[0]}"  # Код возврата false (1)
echo "${PIPESTATUS[1]}"  # Код возврата grep (1)
echo "${PIPESTATUS[2]}"  # Код возврата wc (0)

# Или все сразу:
echo "${PIPESTATUS[@]}"  # Выведет: 1 1 0
```

**Важно:** `PIPESTATUS` доступен только **сразу после выполнения pipe**. Если вы выполните другую команду, массив перезапишется.

```bash
false | true
echo "Проверка"
echo "${PIPESTATUS[0]}"  # ОШИБКА! PIPESTATUS уже перезаписан командой echo
```

---

### Решение 2: `set -o pipefail` (Правильный подход для скриптов)

Если вы хотите, чтобы pipe возвращал **ненужной код**, если **любой** процесс в нем упал, используйте `pipefail`.

```bash
set -o pipefail

false | echo "Hello"
echo $?  # Выведет: 1 (код возврата false!)
```

**Как это работает:**
- Если все процессы завершились с `0`, pipe вернет `0`.
- Если хотя бы один процесс упал, pipe вернет код **последнего упавшего** процесса (не последнего в pipe!).

```bash
set -o pipefail

false | true | grep "notfound"
echo $?  # Выведет: 1 (код возврата false, так как он упал первым)
```

**Рекомендация:** Всегда добавляйте `set -o pipefail` (или `set -euo pipefail`) в начало скриптов, чтобы избежать скрытых ошибок.

---

### Решение 3: Проверка каждого процесса вручную

Если вам нужна сложная логика (например, игнорировать определенные коды ошибок), проверяйте `PIPESTATUS` вручную:

```bash
set -o pipefail

# Пример: grep может вернуть 1, если ничего не нашел, но это не ошибка
result=$(cat file.txt | grep "pattern" | wc -l)
exit_codes=("${PIPESTATUS[@]}")

if [[ ${exit_codes[0]} -ne 0 ]]; then
    echo "Ошибка чтения файла"
    exit 1
elif [[ ${exit_codes[1]} -ne 0 && ${exit_codes[1]} -ne 1 ]]; then
    # grep вернул 1, если ничего не нашел - это нормально
    echo "Ошибка в grep"
    exit 1
fi

echo "Найдено строк: $result"
```

---

### Решение 4: Process Substitution (Альтернатива pipe)

Если вам нужно избежать проблемы с кодами возврата, используйте process substitution (`<()` или `>()`). Это перенаправляет вывод в файловый дескриптор, а не в pipe.

```bash
# Вместо:
cat file.txt | grep "pattern"

# Используйте:
grep "pattern" <(cat file.txt)

# Теперь $? - это код возврата grep, а не cat
```

**Плюсы:**
- Код возврата относится к основной команде.
- Нет проблем с `pipefail`.

**Минусы:**
- Не работает во всех оболочках (только Bash, Zsh).
- Менее читаемо для некоторых.

### Практические примеры

#### Пример 1: Безопасная загрузка JSON
```bash
#!/bin/bash
set -euo pipefail

# Если curl упадет или jq не сможет распарсить, скрипт прервется
response=$(curl -s https://api.example.com/data | jq -r '.key')
echo "Получено: $response"
```

#### Пример 2: Логирование с проверкой
```bash
#!/bin/bash
set -o pipefail

# Логируем вывод команды, но проверяем, что она отработала успешно
if ! output=$(my_command 2>&1 | tee /var/log/my_command.log); then
    echo "Команда упала с кодом: ${PIPESTATUS[0]}"
    exit 1
fi

echo "Команда выполнена успешно"
```

#### Пример 3: Игнорирование ошибок grep
```bash
#!/bin/bash
set -o pipefail

# grep может вернуть 1, если ничего не нашел - это нормально
count=$(cat file.txt | grep "pattern" | wc -l) || true

# Проверяем PIPESTATUS вручную
if [[ ${PIPESTATUS[0]} -ne 0 ]]; then
    echo "Ошибка чтения файла"
    exit 1
fi

echo "Найдено: $count"
```

---

### Чек-лист

1. **Всегда используйте `set -o pipefail`** в скриптах, чтобы pipe возвращал ошибку, если любой процесс упал.
2. **Используйте `PIPESTATUS`** для получения кодов всех процессов в pipe.
3. **Помните:** `PIPESTATUS` перезаписывается после любой команды.
4. **Для сложных сценариев** проверяйте каждый код возврата вручную.
5. **Рассмотрите process substitution** (`<()`) как альтернативу pipe, если нужно избежать проблем с кодами возврата.

Эти техники помогут вам писать надежные Bash-скрипты, которые не пропускают ошибки.
