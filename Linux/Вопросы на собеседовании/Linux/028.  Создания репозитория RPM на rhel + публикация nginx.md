Создание локального YUM/DNF репозитория на базе Red Hat Enterprise Linux (RHEL 8/9) и его публикация по HTTP — это стандартная задача для организации офлайн-зеркала, ускорения загрузки пакетов или распространения своего ПО.

Ниже приведена пошаговая инструкция: мы скачаем Nginx и его зависимости, создадим репозиторий и опубликуем его через веб-сервер Apache (`httpd`).

---

### Шаг 1. Установка необходимых утилит
Нам понадобятся утилиты для скачивания RPM-пакетов, создания метаданных репозитория и веб-сервер для его публикации.

```bash
sudo dnf install -y dnf-utils createrepo httpd
```
* `dnf-utils` — содержит утилиту `yumdownloader` (или `dnf download`).
* `createrepo` — генерирует метаданные репозитория.
* `httpd` — веб-сервер Apache для раздачи пакетов по HTTP.

---

### Шаг 2. Подготовка директории и скачивание пакетов
Создадим директорию для нашего репозитория. Разместим её внутри `/var/www/html/`, чтобы `httpd` мог её сразу отдавать.

```bash
sudo mkdir -p /var/www/html/localrepo/Packages
```

Так как Nginx в базовых репозиториях RHEL может отсутствовать или быть устаревшим, подключим репозиторий EPEL (если он еще не подключен) и скачаем Nginx вместе со всеми зависимостями:

```bash
# Подключаем EPEL (для RHEL 8/9)
sudo dnf install -y epel-release

# Скачиваем Nginx и все его зависимости в нашу папку
sudo dnf download --resolve --destdir=/var/www/html/localrepo/Packages nginx
```
*Флаг `--resolve` критически важен: он скачает не только сам `nginx`, но и все библиотеки (например, `nginx-mod-*`, `openssl-libs` и т.д.), которые нужны для его установки на "чистую" систему.*

---

### Шаг 3. Создание метаданных репозитория
Теперь нужно просканировать папку с пакетами и создать служебную директорию `repodata` с метаданными (списком пакетов, их контрольными суммами и зависимостями).

```bash
sudo createrepo /var/www/html/localrepo
```

---

### Шаг 4. Настройка прав доступа, SELinux и Firewall
Поскольку мы используем RHEL, нужно убедиться, что SELinux и Firewall не заблокируют доступ к репозиторию.

**1. Контекст SELinux:**
Так как мы создали папку внутри `/var/www/html/`, SELinux должен автоматически назначить правильный контекст. Но на всякий случай восстановим его:
```bash
sudo restorecon -Rv /var/www/html/localrepo
```

**2. Настройка Firewall:**
Разрешаем входящие HTTP-соединения:
```bash
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload
```

**3. Запуск веб-сервера:**
Запускаем `httpd` и добавляем его в автозагрузку:
```bash
sudo systemctl enable --now httpd
```

---

### Шаг 5. Проверка доступности репозитория
Узнайте IP-адрес вашего сервера:
```bash
ip a | grep inet
```
Попробуйте открыть в браузере или через `curl` на другой машине:
```bash
curl http://<IP_СЕРВЕРА>/localrepo/repodata/repomd.xml
```
Если вы видите XML-код — репозиторий успешно опубликован.

---

### Шаг 6. Подключение клиента к локальному репозиторию
Теперь настроим клиентскую машину (это может быть тот же самый сервер или любой другой RHEL-сервер в вашей сети) на использование нового репозитория.

Создайте файл конфигурации репозитория:
```bash
sudo nano /etc/yum.repos.d/local-nginx.repo
```

Добавьте в него следующее содержимое:
```ini
[local-nginx]
name=Local Nginx Repository
baseurl=http://<IP_СЕРВЕРА>/localrepo/
enabled=1
gpgcheck=0
```
*(Замените `<IP_СЕРВЕРА>` на реальный IP-адрес вашего RHEL-сервера. Если вы тестируете на этой же машине, используйте `http://127.0.0.1/localrepo/`)*.

*Примечание: `gpgcheck=0` отключает проверку цифровой подписи пакетов. В корпоративной среде рекомендуется настроить GPG-подпись репозитория, но для базового примера мы это пропускаем.*

---

### Шаг 7. Установка Nginx из локального репозитория
Очищаем кэш DNF, чтобы он подхватил новые настройки, и проверяем список репозиториев:

```bash
sudo dnf clean all
sudo dnf repolist
```
*Вы должны увидеть `local-nginx` в списке.*

Теперь устанавливаем Nginx, жестко указав, что брать его нужно именно из нашего локального репозитория:

```bash
sudo dnf install nginx --repo=local-nginx
```

---

### 💡 Полезные советы для продакшена:
1. **Обновление репозитория:** Если вы скачали новые версии пакетов, просто положите новые RPM в папку `Packages` и выполните команду `sudo createrepo --update /var/www/html/localrepo`. Флаг `--update` заставит утилиту пересоздать метаданные только для изменившихся пакетов, что сэкономит время.
2. **Синхронизация с внешним миром:** Если вы хотите сделать полноценное офлайн-зеркало целого репозитория (например, только EPEL), используйте утилиту `reposync`:
   ```bash
   reposync --repoid=epel --download-metadata --download-path=/var/www/html/epel-mirror/
   ```
3. **GPG-подпись:** Для безопасности клиентов в enterprise-среде всегда рекомендуется генерировать GPG-ключ, подписывать им свои RPM-пакеты и файл `repomd.xml`, а публичный ключ распространять среди клиентов.
