Восстановление разметки LVM зависит от того, что именно произошло: была ли удалена таблица разделов, затерт заголовок физического тома (PV) или повреждены метаданные группы томов (VG).

🚨 **ПРАВИЛО №1: Прежде чем выполнять любые команды, создайте посекторный образ диска!**
Любая ошибка при восстановлении может окончательно уничтожить данные. Используйте `dd` или `ddrescue` для создания образа на другой диск:
`ddrescue /dev/sdX /path/to/backup.img /path/to/logfile.log`
*Дальнейшие инструкции предполагают, что вы работаете с образом или готовы к риску.*

---

### Шаг 1: Диагностика
Загрузитесь с LiveCD (например, Ubuntu или SystemRescue) и выполните сканирование:
```bash
pvscan   # Ищет физические тома (PV)
vgscan   # Ищет группы томов (VG)
lvscan   # Ищет логические тома (LV)
```
*   Если `pvscan` **видит** диск, но `vgscan` не находит группу томов — повреждены/удалены метаданные LVM.
*   Если `pvscan` **не видит** диск, но вы уверены, что там был LVM — удалена таблица разделов или затерт LVM-заголовок.

### Сценарий 1: Повреждены или удалены метаданные VG (самый частый случай)
LVM автоматически создает резервные копии своих метаданных в каталогах `/etc/lvm/backup/` и `/etc/lvm/archive/`.

1. **Найдите бэкап.** Если корневой раздел с `/etc` цел, примонтируйте его (например, в `/mnt`) и посмотрите файлы:
   ```bash
   ls /mnt/etc/lvm/backup/
   ls /mnt/etc/lvm/archive/
   ```
   В `backup/` лежат последние версии, в `archive/` — версии с привязкой ко времени (если вы случайно удалили LV и хотите откатиться на состояние вчерашнего дня).

2. **Восстановите метаданные:**
   ```bash
   vgcfgrestore -f /mnt/etc/lvm/backup/имя_вашей_vg имя_вашей_vg
   ```
   *(Если восстанавливаете из archive, укажите полный путь к файлу с нужной датой).*

3. **Активируйте группу томов:**
   ```bash
   vgchange -ay имя_вашей_vg
   ```

---

### Сценарий 2: Случайное выполнение `pvremove` или затирание заголовка PV
Если вы случайно выполнили `pvremove /dev/sdX` или затерли первые сектора диска, LVM перестанет видеть физический том. Но если метаданные VG сохранились в `/etc/lvm/backup/`, их можно восстановить.

1. **Узнайте UUID физического тома** из файла бэкапа:
   Откройте файл `/etc/lvm/backup/имя_vg` в текстовом редакторе. Найдите секцию `physical_volumes` -> `ваш_диск` -> `id = "xxxxxx-xxxx-xxxx-..."`. Скопируйте этот UUID.

2. **Пересоздайте заголовок PV с точным совпадением UUID:**
   ```bash
   pvcreate --uuid "xxxxxx-xxxx-xxxx-..." --restorefile /etc/lvm/backup/имя_vg /dev/sdX
   ```
   *Важно: `--restorefile` указывает LVM, где взять информацию о размере и расположении метаданных, чтобы не затереть ваши данные.*

3. **Восстановите метаданные VG и активируйте:**
   ```bash
   vgcfgrestore -f /etc/lvm/backup/имя_vg имя_vg
   vgchange -ay имя_vg
   ```

### Сценарий 3: Удалена таблица разделов
Если LVM-разметка цела, но операционная система не видит разделы (например, вы случайно переписали MBR/GPT), вам нужно восстановить таблицу разделов.

1. Используйте утилиту **TestDisk**:
   ```bash
   testdisk /dev/sdX
   ```
2. Выберите `[Proceed]` -> `[Intel]` (или GPT) -> `[Analyse]` -> `[Quick Search]`.
3. TestDisk найдет старые разделы (в том числе те, на которых находится LVM). Пометьте их звездочкой `*` (как загрузочные/активные) и нажмите `[Write]`, чтобы сохранить таблицу разделов.
4. После этого выполните `partprobe` или перезагрузитесь, затем `vgscan` и `vgchange -ay`.

### Сценарий 4: Нет бэкапов в `/etc/lvm/` (Катастрофический случай)
Если диск был перенесен на другую машину, или `/etc/lvm` был уничтожен, а области метаданных (MDA) на самом диске повреждены, автоматическое восстановление невозможно.

**Что можно попробовать:**
1. **Поиск сигнатур LVM вручную.**
   LVM оставляет метку `# LVM2 001` в начале физических томов.
   ```bash
   grep -a -b -o "LVM2 001" /dev/sdX
   ```
   Если сигнатура найдена, это значит, что заголовок PV частично цел. Иногда `pvscan --cache /dev/sdX` может заставить LVM перечитать диск и найти VG.

2. **Извлечение метаданных из сырого диска.**
   Если вы знаете, где находится область метаданных (обычно это второй сектор диска, смещение 512 байт или 4096 байт), вы можете попытаться извлечь её через `dd`, прочитать текстовым редактором, найти UUID и структуру, а затем вручную собрать файл формата `vgcfgbackup` и скормить его `vgcfgrestore`. Это требует глубоких знаний формата LVM2.

3. **Профессиональное восстановление.**
   Если данные критичны, а бэкапов нет, **немедленно прекратите любые действия с диском** и обратитесь в лабораторию восстановления данных. Они смогут собрать массив LVM "на коленке" (в RAM или на виртуальном устройстве `dmsetup`), скопировать данные, и только потом восстанавливать файловую систему.

---

### Финальный шаг: Проверка файловой системы
После того как LVM восстановлен и логические тома (LV) активированы (`lvscan` показывает `ACTIVE`), **обязательно** проверьте файловую систему перед монтированием:

```bash
# Для ext4:
e2fsck -f /dev/имя_vg/имя_lv

# Для XFS:
xfs_repair /dev/имя_vg/имя_lv
```

Только после успешной проверки монтируйте разделы и копируйте важные данные!
