Увеличение LVM после расширения виртуального диска состоит из нескольких последовательных шагов: от распознавания нового объема гипервизором до растягивания файловой системы. 

Весь процесс можно выполнить **без перезагрузки** виртуальной машины.

> ⚠️ **Важно:** Перед любыми манипуляциями с разделами и LVM настоятельно рекомендуется сделать снапшот (снимок) виртуальной машины или бэкап важных данных.

Для наглядности будем считать, что ваш диск называется **`/dev/sda`**, а LVM находится на втором разделе — **`/dev/sda2`** (это самый частый сценарий в Ubuntu/Debian/CentOS).

---

### Шаг 1. Заставить ОС увидеть новый размер диска
Если вы только что увеличили диск в панели гипервизора (VMware, Proxmox, Hyper-V, AWS и т.д.), Linux мог не заметить изменений.
1. Узнайте имя диска:
   ```bash
   lsblk
   ```
2. Заставьте ядро перечитать размер диска (замените `sda` на ваш диск):
   ```bash
   echo 1 | sudo tee /sys/class/block/sda/device/rescan
   ```
3. Снова проверьте `lsblk` или `sudo fdisk -l`. Вы должны увидеть, что размер самого диска (`sda`) увеличился, но размер раздела (`sda2`) и LVM пока остались прежними.

---

### Шаг 2. Увеличить размер раздела (Partition)
*Пропустите этот шаг, если LVM создан напрямую на весь диск без таблицы разделов (то есть PV — это `/dev/sda`, а не `/dev/sda2`).*

Самый простой и безопасный способ — использовать утилиту `growpart`.
1. Установите её (если не установлена):
   * Ubuntu/Debian: `sudo apt install cloud-guest-utils`
   * CentOS/RHEL/Alma: `sudo yum install cloud-utils-growpart`
2. Увеличьте раздел до максимального доступного размера:
   ```bash
   sudo growpart /dev/sda 2
   ```
   *(Обратите внимание на пробел между именем диска и номером раздела!)*
3. Проверьте `lsblk`. Теперь размер раздела `sda2` должен совпадать с размером диска `sda`.

---

### Шаг 3. Растянуть Physical Volume (PV)
Теперь нужно сказать LVM, что физический том стал больше.
```bash
sudo pvresize /dev/sda2
```
*(Если у вас LVM на целом диске, команда будет `sudo pvresize /dev/sda`)*.

Проверьте, появилось ли свободное место в группе томов (Volume Group):
```bash
sudo vgs
```
В колонке `VFree` вы должны увидеть newfound свободное место.

---

### Шаг 4. Увеличить Logical Volume (LV) и файловую систему
Вам нужно узнать путь к вашему логическому тому. Посмотрите его через `lsblk` или `df -h`. Обычно он выглядит как `/dev/mapper/имя_vg-имя_lv` (например, `/dev/mapper/ubuntu--vg-ubuntu--lv` или `/dev/mapper/cl-root`).

Современный LVM позволяет растянуть и сам том, и файловую систему внутри него **одной командой** с помощью флага `-r` (resizefs).

Выполните команду, указав ваш LV и флаг `-l +100%FREE` (занять всё свободное место в VG):
```bash
sudo lvextend -l +100%FREE -r /dev/mapper/ваш_vg-ваш_lv
```

*Примечание: Флаг `-r` автоматически определит файловую систему (ext4, xfs, btrfs) и растянет её. Если по какой-то причине `-r` не сработал, растянуть ФС вручную можно так:*
* *Для **ext4**: `sudo resize2fs /dev/mapper/ваш_vg-ваш_lv`*
* *Для **xfs**: `sudo xfs_growfs /` (указывается точка монтирования, а не устройство!)*

---

### Шаг 5. Проверка результата
Выполните команду:
```bash
df -h
```
Теперь в строке с вашей корневой (или нужной) файловой системой вы увидите увеличенный объем.

---

### 💡 Краткая шпаргалка (если LVM на разделе `/dev/sda2`):
```bash
# 1. Перечитать диск
echo 1 | sudo tee /sys/class/block/sda/device/rescan

# 2. Растянуть раздел
sudo growpart /dev/sda 2

# 3. Растянуть PV
sudo pvresize /dev/sda2

# 4. Растянуть LV и ФС (вместо /dev/mapper/... подставьте свой путь из df -h)
sudo lvextend -l +100%FREE -r /dev/mapper/ubuntu--vg-ubuntu--lv
```
